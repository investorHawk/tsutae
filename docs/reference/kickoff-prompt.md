# 新フォルダでの最初のプロンプト(2026-11-03)

用途: 空のプロジェクトフォルダで Claude Code を起動し、最初に貼り付ける。`<APP_NAME>` はアプリ名に置き換える。

---

あなたはこのプロジェクトの仕様策定パートナーです。私は消化器外科医で、ハッカソン「Built with Claude (Code): Japan 2026」(提出期限 2026-11-10 14:00 JST、ソロ参加、公開リポジトリ必須、期間中の新規制作のみ)に `つたえ` を出します。

## まず読むもの
企画はすでに別フォルダで練ってあります。実装や質問を始める前に、次の2ファイルを読んでください。
- 構成案(正本): `docs/reference/concept.md`
- 大会ルール・禁止例・審査基準: `docs/reference/event-rules.md`

構成案で決まっていることは蒸し返さないでください。特に次は確定です。
- 対象: 外来化学療法中の消化器がん患者(FOLFOX/CAPOX)。末期・緩和ケアは対象外
- 患者が毎日、ワンタップ(「つらくて書けない」)/クローズ質問/自由記載で記録する。音声は MVP 外
- Claude が日付・コース日数・標準用語・引用つきの時系列に直し、医師が決めた形式のレポートにする
- 受診時に患者が院内QRを読むと、医師の手元にレポートが印刷される。患者のスマホには表示しない
- AIは重さを判定しない・トリアージしない・患者にAIの文を出さない。患者識別情報は伏せてから Claude に送る
- 欠けた記録を「症状なし」で埋めず、「入力なし/つらくて書けない/症状なし」を区別する
- 変換パイプラインは Claude Agent SDK の上に作る(Skills / subagents / hooks を Claude Code の機能として見せる)
- スタック: React + FastAPI + SQLite。デモデータは全て合成
- 効果の主張: 聞き取り 約3分 → 約30秒、問診の抜けが減る(実感値、未測定と明記)

## この最初のセッションでやること
**今日はコードを書きません。仕様書を作ります。**

1. 2ファイルを読んだら、構成案の「未確定」と、実装するうえで決めないと進めない点を洗い出してください。
2. それらを **AskUserQuestion で、1回に1〜3問ずつ**、私に聞いてください。選択肢には推奨案を先頭に置き、理由を一行で添えてください。私にしか決められないこと(臨床の運用・外来の実態・優先順位・UIの好み)だけを聞き、技術的に自分で調べられること(Agent SDK の hooks / subagents / skills の対応、印刷CSSの可否など)は自分で確認して結果を報告してください。
3. 想定している質問の領域(順番の目安):
   - レジメンの投与スケジュールとコース日数の数え方、クローズ質問の初期セット(FOLFOX/CAPOX)
   - 医師形式レポートの初期案(A4一枚に何を、どの順で)。先生の外来での読み方に合わせる
   - 受診時の流れ(QRの置き場所、受付番号の入れ方、印刷先、生成の前夜バッチ)
   - 欠けた日・代理入力・回想入力の表示方法
   - 緊急時の固定規則(発熱など)の文言と、デモで見せる範囲
   - 伏せ字にする情報の範囲(氏名・電話・病院名・地名・日付はどうするか)
   - 合成データの設計(患者何人、何コース、どんな食い違いを埋め込むか)と精度評価の指標
   - デモ動画の筋書きで必要になる画面
4. 質問が終わったら `docs/spec.md`(仕様書)、`docs/decisions.md`(決めたことと理由、日付つき)、`docs/plan.md`(11/10までの日程、必須/余力の区分)を書いてください。仕様書には「AIがしないこと」「患者情報の扱い」「既存品(Juno、国内ePRO)との違い」の節を必ず入れてください。
5. 最後に `git init`、`.gitignore`、`README.md` の骨組み(一行目に「症例は全て合成」)を作り、最初のコミットをしてください。コミットは Conventional Commits で。
