# 決めたことと理由

形式: 日付 / 決定 / 理由 / 出どころ（ユーザー＝先生の回答、仮置き＝Claude の提案で承認待ち）。企画段階で確定済みの事項は `docs/reference/concept.md` にあり、ここには仕様策定（2026-11-03）以降に決めたことだけを書く。

## 2026-11-03 仕様策定セッション

### 技術確認（自分で調べた事実）
| 決定 | 理由・根拠 |
|---|---|
| 変換パイプラインは Python `claude-agent-sdk` で作る。hooks / subagents / skills は全て使える | 公式ドキュメントで確認。Python SDK は `PreToolUse` `PostToolUse` `UserPromptSubmit` `Stop` `SubagentStart/Stop` に対応。`agents={name: AgentDefinition(...)}`、`.claude/skills/<name>/SKILL.md` + `setting_sources=["project"]` |
| Python 3.12 を uv で入れる | SDK は Python 3.10+。このMacのシステム Python は 3.9.6 |
| 認証は `ANTHROPIC_API_KEY`（大会配布クレジット） | 公式に「claude.ai ログインを Agent SDK 製品に使うことは不可」と明記 |
| PRO-CTCAE の文言は使わない。項目分類を参考にした独自文言 | Terms of Use: 無料だが「改変・翻訳・派生物は NCI の書面同意なしに禁止」 |
| 標準用語は CTCAE v5.0 日本語訳 JCOG 版の有害事象名を数十語、出典表記つきで使う | JCOG: 非営利利用は許諾不要。「有害事象共通用語規準 v5.0 日本語訳JCOG版より引用」と記載する。営利利用は別契約（README に注記） |
| 印刷はブラウザ印刷 → PDF。実機印刷は別 Mac | ブラウザからの無音印刷は不可能。先生のプリンタは別 Mac から出す運用 |

### 範囲
| 決定 | 理由 | 出どころ |
|---|---|---|
| FOLFOX を合成データ・評価まで完走。CAPOX は Skill のみ | 7日間で評価の数字を確実に出す。レジメン別設定は Skill で示せる | ユーザー |
| 投与日を Day1、次の投与前日まで | 臨床で一般的。ポンプ抜去日を Day3 と表現できる | ユーザー |
| 延期は医師が実投与日を登録し、Day を数え直す。AI は理由を推測しない | 前コースとの Day 比較を狂わせない | ユーザー |

### 患者の入力
| 決定 | 理由 | 出どころ |
|---|---|---|
| クローズ5問: しびれ・下痢・口内炎・吐き気/食欲・発熱 | FOLFOX の主要毒性に絞る。手足症候群は CAPOX 側へ | ユーザー |
| 回答は3段階「なし／ある／つらい」 | 体調の悪い日でも押せる。Grade を患者に選ばせない | ユーザー |
| 発熱は「熱を測りましたか」→ 測った場合のみ体温を数値入力 | 未測定と平熱を区別。固定規則の閾値判定に使える | ユーザー |
| 代理入力は「本人／家族が代わりに」トグルだけ。レポートに「代」 | 家族アカウントを作らず小さく実装 | ユーザー |
| 回想は自由記載から AI が日付を戻し「回想」印。専用画面なし。空白は空白のまま | 時間表現の正規化で扱える。「欠けを情報として扱う」と干渉しない | ユーザー |
| 仮名ID は院内で登録用 QR（仮名ID入り URL）を渡し、スマホが記憶。パスワードなし | 体調の悪い患者にログインを課さない。対応表は院内の紙だけ | ユーザー |
| 自分の記録一覧（編集なし）を MVP に入れる | 「見られないのは AI のまとめだけ」の説明が成立する | ユーザー |
| 記録に `skill_version` を保存し、質問追加前の日は「未設問（−−）」で表示 | Skill 書き換えが翌日から効くため、「入力なし」と混ざると欠けの意味が崩れる | 仮置き |

### レポート
| 決定 | 理由 | 出どころ |
|---|---|---|
| 順序: ヘッダ → 要確認 → 経過表 → 症状別時系列 → 引用 | 最初の5秒で要確認だけ読めば済む | ユーザー |
| 経過表のセルはクローズ回答、自由記載由来は ○ を重ねる。統合しない | 統合は AI の判断になり「食い違いを解決しない」方針と矛盾 | ユーザー |
| Grade は一切出さない。企画の「Grade 候補 2 以上を太字」は落とす | 「重さを判定しない」と矛盾し、医療アドバイス AI に近づく | ユーザー |
| 欠けの表示: 入力なし=空白、つらい=列全体を斜線、症状なし=薄い「−」 | モノクロ印刷で区別できる。「つらい」は日単位の出来事と分かる | ユーザー |
| 前コースの行はクローズ回答のみ（AI 変換は今コースだけ） | QR 時に全生成＋印刷後削除の方針だと、前コースも毎回再変換になり待ち時間とコストが2倍になる | ユーザー（2026-11-03 確定） |
| Claude 失敗時はクローズ経過表＋原文引用のみのレポートを「AI変換なし」と明記して印刷できる | 「安心してそのまま使える」ための必須フォールバック | 仮置き |

### 受診時の流れ
| 決定 | 理由 | 出どころ |
|---|---|---|
| QR 読取後に当日の受付番号を入力し、レポートに印字 | その日限りの番号で識別性が低い。Claude には送らない | ユーザー |
| QR は診察室前の待合に掲示。印刷先は診察室のプリンタ（MVP は PDF） | 待ち時間に読めば診察前に紙が届く | ユーザー |
| 生成は QR 時に全部行う。前夜バッチなし | 患者は待合で待つので数分かかってよい。サーバーに中間データを溜めない | ユーザー |
| 印刷後にレポートと変換結果を削除。紙は電子カルテの文書管理にスキャン登録（院内運用） | AI の成果物をサーバーに蓄積しない | ユーザー |
| 削除の条件は「医師の印刷済みボタン or 24 時間 TTL」 | 別 Mac から PDF を印刷するため、印刷完了を機械的に検出できない | ユーザー（2026-11-03 確定） |

### 安全・個人情報
| 決定 | 理由 | 出どころ |
|---|---|---|
| 緊急固定規則: 38.0℃以上で施設の既存案内文をそのまま表示。判定はコード。デモでは設計として触れるだけ | 患者向け表示の唯一の箇所。医療アドバイス AI に見える危険を最小化 | ユーザー |
| 伏せ字: 人名・電話・メール・住所・病院名。日付・年齢・地域名は残す | 日付は正規化に必須。年齢は送らない | ユーザー |
| 伏せ字漏れの疑いがある記録はその記録だけ送信を止め、レポートに「未処理の記載あり」 | 誤検知一つでレポート全体が出なくなるのを避ける | ユーザー |
| 置換規則（一次）と Hook の検出規則（二次）を別物にする | 同じ規則なら Hook は永遠に発火せず、検証もデモもできない | 仮置き |
| PII の砦は `UserPromptSubmit`。`PreToolUse` では最初のプロンプトを検査できない | Agent SDK の仕様 | 仮置き（技術判断） |
| パイプラインの出力はカスタムツール経由にし、`PreToolUse` で引用一致を機械検査 | サブエージェントがテキストを返すだけでは Hook で検査できない | 仮置き（技術判断） |
| Skill 書き換えの `Write/Edit` は `.claude/skills/` 配下に限定する Hook を置く | 無いとエージェントがサーバーの任意ファイルを書ける | 仮置き（技術判断） |
| 「患者に AI 文を出さない」はアーキテクチャ（患者 API がレポート表を読まない）＋ Hook の二層。Hook だけを根拠にしない | Python SDK に表示系 Hook（`MessageDisplay`）が無い。本質は経路の分離 | 仮置き（技術判断） |

### 合成データ・評価
| 決定 | 理由 | 出どころ |
|---|---|---|
| デモ用1人×3コース＋評価用2人×2コース（約42日、自由記載約60件） | デモは第3コースで前コース比較を見せる。評価は別人で「デモに合わせた」と見られない | ユーザー |
| 難ケース必須: 矛盾／軽い・改善中／相対時間／否定表現 | IBD 研究で判明した LLM の弱点と、日付正規化・偽陽性の指標 | ユーザー |
| 合格ラインは置かず実測値と失敗例を出す | 小さな合成データで合格ラインを置くと過大な主張に見える | ユーザー |
| 指標5「引用一致率」を追加 | 選ばれた4ケースでは幻覚引用を測れない | 仮置き |
