# 毎日の通知とスマホ保存への移行 仕様書

- 作成: 2026-11-06（先生との壁打ちから。判断の記録は `docs/decisions.md` の同じ名前の節）
- 状態: 承認済み。§13 のうち PR A の分は `docs/spec.md` に反映済み（PR B・PR C の分は、それぞれの実装の PR で入れる）
- 期限: 撮影 2026-11-08 13:00、提出 同日 20:00

## 1. 目的と範囲

| 作るもの | 目的 |
|---|---|
| 毎日の通知 | 記録の抜けを減らす。ホーム画面アプリに1日1回、固定文で促す |
| スマホ保存への完全移行 | サーバーに余計なデータを持たない。記録はスマホに置き、受診のときだけサーバーへ送る。印刷済みか 24 時間で消す |
| 受診タブ | ホーム画面アプリから記録を送る。院内 QR はやめる |
| 2台目のスマホ（最後に作る） | 家族のスマホの記録も同じ受付にまとめる |

### 変えないこと

- 患者のスマホに AI の文を出さない。通知の文は `patient_strings.json` の固定文
- 変換は DB の `entries` を読む。`make eval`・`run_demo_visit.py` の仕組みも変えない
- Claude に送る前の伏せ字（一次・二次）、Hook H1〜H4、D6 の流れ、レポートの Jinja2 描画
- 受診と受診の間に医療機関へは通知しない（通知は患者への促しだけ）

### 作らないこと（提出版）

- オフラインでの記録・画面のキャッシュ。Service Worker は通知専用で `fetch` を扱わない
- 暗号化した控え。消えた記録は復元せず、紙に「届いていない」と示す
- Declarative Web Push の別経路（iOS 18.4 以降）。Android には無いので、標準の Web Push に揃える
- 既存の DB の記録を端末へ移すこと（全て合成データ。撮影は新しい DB で始める）

## 2. 全体の流れ

```
登録: 登録用 QR →（iPhone は Safari で案内だけ）→ ホーム画面に追加 → アプリで番号を入れる → 設定で通知をオン
毎日: 通知 → /today → 記録 → サーバーは日付の印と時刻を返す → 端末に保存
受診: 受診タブ → 受付番号 → 範囲内の記録を送る → entries に一時保存 → 変換 → D3
印刷: 印刷済み or 24 時間 → レポート・変換結果・受付番号と一緒に、送られた記録も消す
```

サーバーに残るのは、仮名ID・レジメン・実投与日・質問集の版・日付の印・通知の登録・文面なしのログ。

## 3. 前提の環境（先生の作業）

### HTTPS: Tailscale Funnel

- 固定 URL `https://<Mac 名>.<tailnet>.ts.net` を使う。URL が変わるとホーム画面アプリ・通知の登録・端末の記録が別物になるので、Quick Tunnel は使わない
- iPhone 側の設定は要らない。アプリには URL が出ないので、動画でも見えない。公開リポジトリに実際の URL は書かない
- 外から届くので、撮影の前後以外は止める。`DOCTOR_PASSWORD` と `TSUTAE_SECRET` は既定値にしない（`settings_check.py` が止める）

```bash
# Tailscale のアプリを入れてログインし、管理画面で HTTPS と Funnel を許可する（コマンドは導入時に確かめる）
TSUTAE_TODAY=2026-11-09 TSUTAE_PUBLIC_BASE_URL=https://<Mac 名>.<tailnet>.ts.net make dev-api   # 鍵・パスワードも渡す
(cd frontend && npm run build && npx vite preview --host 127.0.0.1 --port 5173 --strictPort)
tailscale funnel --bg 5173   # preview が動いてから開く
caffeinate -dims   # 通知の時刻に Mac を眠らせない
```

- **Funnel に出すのは `vite preview` だけ。開発サーバーは出さない**。今の Vite 5.4.8 の開発サーバーは `/@fs/<絶対パス>?import&raw??` で `server.fs` の検査を抜け、インターネットから `.env` や DB を読まれる。preview は `dist/` の中だけを返し、`/api` は `server.proxy` を引き継いで 8000 へ渡す（`frontend/src/previewServing.test.ts`）。画面を直したら `npm run build` からやり直す
- 今の Vite 5.4.8 に `allowedHosts` の検査は無い（`node_modules` で確認）。上げるときは `preview.allowedHosts` に `.ts.net` を足す
- `public_base_url` が https になると Cookie に `Secure` が付く。医師画面は同じ URL か localhost で開く
- 今の `http://192.168.1.9:5173` のホーム画面アプリは別のオリジンなので、追加し直す

### 実機

iPhone（iOS 18 以降）だけで確かめる。Android の端末は無いので、README に「実機で未確認」と書く。

### 通知の鍵（VAPID）

`scripts/gen_vapid.py` で作り、`.env` に `TSUTAE_VAPID_PUBLIC_KEY`・`TSUTAE_VAPID_PRIVATE_KEY`・`TSUTAE_VAPID_SUBJECT`（`mailto:`）を書く。コミットしない。無いときは起動を止めず、通知だけ「使えません」にする。

## 4. 毎日の通知（PR A）

### 4.1 決まり

| 項目 | 決まり |
|---|---|
| 回数 | 1日1回まで。催促の再送はしない |
| 時刻 | 端末ごとに患者が 30 分刻みで選ぶ。既定 20:00 JST。サーバーに置く |
| 送らない条件 | 今日の日付の印がある（どの端末で書いても）。「つらくて書けない」も書いた扱い |
| 送る期間 | コースが登録され、今日が「最後のコースの Day1 ＋ 1コースの日数 ＋ 14 日」以内。D2 で次のコースを入れると再開する |
| サーバーが止まっていた分 | 送り直さない。時刻から 10 分を過ぎたらその日は送らない |
| タイトル | `つたえ` |
| 本文 | `今日の記録をお願いします。つらい日はボタンひとつで記録になります。` |
| 押したとき | `/today` を開く |
| バッジ | 通知で 1。アプリを開くか記録すると消す。Android は点だけのことがある |
| 音 | 端末の通知音。独自の音は選べない。消音モードでは鳴らない |
| 入れない文 | 症状・レジメン名・薬の名前・AI の文 |

### 4.2 Service Worker（`frontend/public/sw.js`）

- `push` で必ず `showNotification` する（`event.waitUntil` の中）。iPhone は通知を出さない push が続くと登録を取り消されるおそれがあるので、**端末側で握りつぶさない**。送るかどうかはサーバーで決める
- 本文が読めないときも、タイトルだけの通知を出す
- `notificationclick` で `/today` を開く。`fetch` のハンドラは書かない（オフラインは範囲外）
- すでに `/today` の画面があれば読み直さない（書きかけを消さない）。ただし画面の今日とサーバーの今日が違うときは読み直す（前の日の「記録しました」を残さない）。戻ったときも同じ
- 登録は設定タブで患者がオンにするときだけ。許可はボタンを押したときだけ求める

### 4.3 サーバー

- 依存: `pywebpush`（2026-11-06 時点の最新は 2.5.0。動くことは導入時に確かめて版を固定する）
- 送信のループ: `_purge_loop` と同じく lifespan の中。`--workers 1` が前提。1 分ごとに対象を探し、`asyncio.to_thread` で送る。送る処理は差し替えられる形にしてテストする
- 時計は `config.now()`・`today()`（`TSUTAE_TODAY` でも動く）
- `last_sent_date` で二重に送らない。404・410 の登録は消す。TTL は 3600 秒
- ログは件数と例外の型名、送信先が返した状態コードだけ。仮名ID・endpoint は出さない

| 経路 | 用途 |
|---|---|
| `GET /api/patient/push-config` | 公開鍵と、通知を使えるか |
| `PUT /api/patient/{pid}/push-subscription` | 登録・時刻の変更（endpoint で一意） |
| `DELETE /api/patient/{pid}/push-subscription` | この端末の通知を切る |
| `POST /api/patient/{pid}/push-test` | 試しに送る。10 秒後に同じ文を1回。登録ごとに1分に1回まで（患者ごとの合計にも上限）。**印・送る期間・時刻の条件は見ない**（撮影の日付でも必ず届くように） |

- 1人の患者の登録は5件まで。超えたら古い行から消す（送信のループと試送の回数を、1人の患者が増やせないように）
- 新しい経路も `reports`・`timelines`・`regimen_drafts` を読まない。送る文字列は `patient_strings.json` からだけ（アーキテクチャテストに足す）

### 4.4 日付の印

```
record_marks(patient_id, record_date, last_marked_at, PK(patient_id, record_date))
push_subscriptions(id, patient_id, endpoint UNIQUE, p256dh, auth, notify_time, last_sent_date, created_at)
```

PR A の時点では `POST /entries` が印も書き、既存の `entries` から印を作る移行も入れる。こうすると、スマホ保存が判定で外れても通知はそのまま動く。

### 4.5 設定タブ（`/settings`）

下のタブは「今日の記録／これまでの記録／受診／設定」の4つ（受診は PR B で足す）。

- 毎日のお知らせ: オン・オフ、時刻、試しに通知を送る
- オフのあいだ、今日の記録に案内の帯を1つ出す
- 使えないとき（鍵が無い・許可が拒否された・未対応の端末）は理由と次の操作を定型文で出す。拒否された後は端末の設定から直す案内を出す
- 文言は全て `patient_strings.json`（`noHardcodedText.test.ts` の対象）

## 5. スマホ保存（PR B）

### 5.1 端末の保存

- IndexedDB（DB `tsutae`、store `entries`、キー `client_entry_id`、索引 `[pid, record_date]`）。薄い包みを自分で書き、テストは dev 依存の `fake-indexeddb` で行う
- 1件の中身: `pid`・`client_entry_id`（UUID）・`recorded_at`・`record_date`・種類・`by_proxy`・`skill_version`・回答・質問の文の写し・自由記載
- 仮名ID ごとに分ける。別の番号で登録しても、他の患者の記録を見せず、送らない
- 最初の保存のときに `navigator.storage.persist()` を試す。結果に頼らない
- 残す期間: 患者が消すまで。次の受診に前コースが要り、P2 で見返せる

### 5.2 記録の順序（オンライン必須）

1. `GET /questions`: 今日の日付・質問集・固定規則を受け取る
2. `POST /api/patient/{pid}/record-marks`（本文なし）: サーバーが今日の印を付け、`record_date`・`recorded_at` を返す
3. IndexedDB に保存する。**端末の時計は使わない**ので、Day はずれない
4. 完了を出す。バッジを消す。固定規則に当たれば案内を出す

- 2 が失敗: 「送れませんでした」と出して入力を残す。`client_entry_id` は押し直しても同じ
- 3 が失敗: 同じくやり直せる。印だけが残ると紙に「届いていない」と出るので、事実と違う表示にはならない
- 圏外では書けない（README に書く）

### 5.3 38℃ の案内（固定規則）

`GET /questions` に `fixed_rules`（質問の key・閾値・`patient_string_key`）を足し、画面のコードで比べる。**体温はサーバーに送らない**。モデルは関わらない（spec §11 のとおり）。Python と TypeScript の判定は同じ表でテストする。

### 5.4 P2 と取り消し

- P2 は端末の記録を読む。受診日は新しい `GET /{pid}/visit-days` から（日付と受付の時刻だけ）
- 「つらくて書けない」の取り消し（技術判断）: サーバーは記録の種類を持たないので、端末が `POST /{pid}/record-marks/undo` に `{recorded_at, clear_mark}` を送る。`recorded_at` はその記録を保存したときにサーバーが返した値、`clear_mark` は「その日に端末の記録が他に無い」とき true。サーバーは自分の時計で `recorded_at` から 10 分以内か、その後に受付が無いかを確かめ、外れれば 409。通れば端末の記録を消す。端末の時計は使わない
- `POST /entries`・`GET /entries`・`POST /entries/{id}/undo` は患者 API から外す

### 5.5 受診タブと受付

`POST /api/visit` の本文に `entries` を足す。

1. 受診タブ `/visit` で受付番号を入れる
2. `GET /{pid}/visit-window`: 送る範囲（前コースの Day1〜今日）
3. 範囲内の記録を `POST /api/visit` で送る
4. 検査 → `entries` 系に一時保存 → 変換（今と同じ）→「先生に届けました」

**受け取りの検査**（外からの入力）:

- 記録は 500 件まで、本文は 5MB まで、記録日は範囲内で未来でないこと、`client_entry_id` は UUID 形式か見本の形式
- 回答は**その記録の版**の質問集と照らす（今の版ではない）。不正が1件でもあれば全体を 422 にして何も保存しない
- `(patient_id, client_entry_id)` は一意。送り直しは二重にならない

**消す**:

- 印刷済み、または 24 時間 TTL で、その患者に開いた受診が他に無ければ、受付で受け取った記録（`client_entry_id` のある行）を同じトランザクションで消す
- `client_entry_id` の無い既存の行は消さない

**残る課題（受け入れる）**: 受付から印刷まで、伏せ字の前の原文がサーバーに置かれる。D6 で原文が要るので、端末で伏せ字にはしない。

### 5.6 届いていない記録

- 今コースの `record_marks` の日付のうち、受け取った記録に無い日を「届いていない日」とする
- 紙: 要確認に `記録が届いていない日: Day5, Day6`、ヘッダの内訳に `届いていない N`。**経過表は空白のまま**で、「入力なし」には数えない
- `ReportData` に足す。Claude には送らない。A4 一枚に収まることを確かめる
- 同じ日に別の端末の記録があれば、その日は届いた扱い（日付の単位なので、片方の中身が欠けても分からない）

### 5.7 医師画面

- D1 の「最後の記録日」「3日以上記録なし」は `record_marks` から出す。今と同じ表示を保つ
- D2 の記録の一覧は受付の間だけ中身が出る。それ以外は「記録は患者さんのスマホにあります。受付の後に表示されます」
- D3・D5・D6 は変えない

### 5.8 登録の入口（院内 QR をやめた後）

- 登録用 QR と番号は残す。QR は「アプリを入れる入口」
- iPhone の Safari（ホーム画面の外）では、全ての患者画面で「ホーム画面に追加」の案内だけを出す。**記録させない**。URL に番号があれば大きく見せる
- 判定は純関数にする（iPhone・iPad・`navigator.standalone`）。Android のブラウザは保存先が同じと見込み、記録を許して追加を勧める（実機で未確認）
- アプリの中で番号を入れて登録する（今の `NotRegistered` を使う）

### 5.9 登録と記録を消す

設定の「このスマホの登録と記録を消す」は、2段階の確認の後で次を行う。

- `POST /{pid}/unregister`（本文に `endpoint`。通知を登録していなければ null）: この端末の通知の登録を消し、Cookie を消す。ブラウザの通知の登録も解除する
- 端末の仮名ID と、その患者の記録を消す

`record_marks` は消さない（他の端末と D1 が使う）。設定に「ホーム画面のアイコンを消すと記録も消えます」を出す（実機で確かめてから文を決める）。

### 5.10 撮影用の見本

- `TSUTAE_DEMO_TOOLS=1` のときだけ、デモ患者の設定に「見本の記録を入れる」を出す
- `GET /{pid}/demo-entries` は同じ環境変数のとき、デモ患者にだけ合成データの記録を `demo-<seq>` の ID で返す。無いときは 404
- 押し直しても増えない。撮影の DB は `scripts/seed_demo.py --device-records` で作り、患者・コース・印を入れて `entries` には入れない（入れると受付で二重に数える）。既定の動きは、既存のテストが使うので変えない。`run_demo_visit.py` は自分で記録を入れるので変えない
- `TSUTAE_DEMO_TOOLS` が無ければ、画面にもボタンにも API にも出さない。テストで固定する
- 撮り直し: 新しい DB を作る → 設定で消す → 登録し直す → 見本を入れる

## 6. 2台目のスマホ（PR C。最後に作り、間に合わなければ外す）

- 家族のスマホでも同じ番号で登録できる。通知の時刻は端末ごと
- 家族は**同じ受付番号**を受診タブで入れて送る。番号は患者から聞く
- 受け取り: `client_entry_id` で統合する。新しい記録が1件以上あれば自動で変換し直す

| 受診の状態 | 動き |
|---|---|
| 生成中 | `regen_pending` を立て、終わったら1回だけ変換し直す |
| ready・failed | すぐ変換し直す。前のレポートは残り、終わると置き換わる |
| 印刷済み（今日） | 409。「すでに先生に届いています。受付でお声がけください」。記録は端末に残る。印刷で受付番号が消えるので番号では見分けられず、**その患者に今日の印刷済みの受診があれば、どの端末・どの番号でも断る**（今は新しい受診ができる。1台の患者も変わる。同じ日の2回目の受診は受付で扱う。先生の確認待ち） |
| 新しい記録が無い | 変換し直さない（今の送り直しと同じ） |

- 自動の変換し直しは1受診3回まで（費用の歯止め）。超えたら記録だけ受け取り、D3 に「追加の記録あり」を出す。医師が「AI でもう一度変換」を押せる
- D3 の変換中は印刷できない（今の `refuse_generating`）。行に「記録が追加され、作り直しました」を出す。**先に別タブで開いたレポートは古いまま残るので、D3 の札で知らせる**
- `begin_regeneration` の「AI の結果の ready は不可」を、記録が増えたときだけ通す。ログは `regenerate_requested`（文面なし）
- 番号を間違えると別の受診ができ、D3 に2行出る（今の動きと同じ。どちらも全ての記録で変換する）
- 外すとき: README に「家族の代理入力は本人のスマホで」と書く。別のスマホの記録は紙で「届いていない日」になる

## 9. テスト

TDD で進める。Claude API は呼ばない。

| 区分 | 確かめること |
|---|---|
| backend | 送る・送らないの判定（印あり・期間外・コースなし・時刻前後・10 分超え・二重送信）、周期＋14 日の境目、404・410 で消す、鍵なしで起動する、試送の上限、受付の検査（型違い・古い版・未来・件数）、送り直しの統合、印刷と TTL で消す（既存の行は残す）、届いていない日、`TSUTAE_DEMO_TOOLS` なしで 404 |

### 実機（先生の iPhone）

**PR A**: Funnel で開く → 追加 → 番号 → オン → 試送がロック画面に届く → 押すと `/today` → バッジが付いて消える → 指定した時刻に届く → 記録した日は届かない → オフで届かない

毎日の送信は `TSUTAE_TODAY=2026-11-09` で動かして確かめる（または日付の印の無い患者で）。`make seed` の `P-DEMO0001` には 11/7・11/8 の印があり、実際の日付で動かすとこの2日は記録していなくても届かない（試送は印を見ないので届く）。「指定した時刻に届く」の後は同じ日にもう届かないので（§4.1）、「記録した日は届かない」は次の日で確かめる。サーバーを起動し直すと日付が戻るので、そのときは `TSUTAE_TODAY=2026-11-10` にする。

**PR B**: 記録して閉じ、開き直しても P2 にある → 再起動後もある → 見本を入れる → 受診タブで送る → D3 → A4 → 印刷済みで DB の記録が消える → 38℃ の案内 → 取り消し → 消す → Safari は案内だけ → 通信を見て、記録のときに本文を送っていない

**実機で初めて分かること（結果を decisions に書く）**: 消音モードの音、バッジの実際の動き、アイコンを消すと記録が消えるか、`persist()` の結果、再起動後の通知

- [Quick Tunnels（Cloudflare）](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/): URL が毎回変わるので採らなかった
