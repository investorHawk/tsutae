# FOLFOX の記録を時系列に直すための指示

外来化学療法 FOLFOX 中の患者が残した記録（伏せ字済み）を、暦日・コース日数（Day）・標準用語・原文引用つきの出来事に直すときに読む。読むのは変換パイプラインの主エージェント（統合役）と、そこから呼ばれる3役（date-normalizer / term-mapper / contradiction-finder）。

- 上の frontmatter はアプリが読む設定で、質問文・回答の型・固定規則の正本。本文はそれを言い換えない
- 症例は全て合成（架空）

## 1. 投与スケジュール

- 1コースは14日。**Day1 = 実投与日**（外来で点滴した日）
- Day1 に外来で点滴し、続けてフルオロウラシルを46時間かけて入れる持続ポンプ（携帯型）をつけて帰宅する
- **Day3 にポンプを外す**（ポンプ抜去日。入力の `schedule.pump_removal_date`）
- 今コースは次コースの実投与日の前日まで。Day14 までが標準だが、それを過ぎた記録も今コースの Day15, Day16… として数える
- 延期があっても Day は医師が登録した実投与日から数える。延期の理由は推測しない・書かない
- 日付の手がかりは入力の `schedule`（`day1_date`・`pump_removal_date`・`last_day_date`・`previous_infusion_date`）と、各記録の `record_date`（記録日）・`day`

## 2. 相対時間表現の直し方（date-normalizer）

出来事ごとに暦日 `date` と `day` を決める。基準は**その記録の記録日**（`record_date`）。受診日や今日ではない。

| 表現 | 直し方 |
|---|---|
| 今日・さっき・今朝・今夜 | 記録日 |
| 昨日・昨夜 | 記録日の1日前 |
| おととい | 記録日の2日前 |
| 点滴の日・投与日・病院で点滴した日 | Day1（実投与日） |
| 点滴の次の日・点滴の翌日 | Day2 |
| ポンプを外した日・ポンプを抜いた日 | Day3（ポンプ抜去日） |
| ポンプを外した次の日 | Day4 |
| 「木曜に」のように先週・今週が付かない曜日 | 記録日以前で最も近いその曜日（記録日がその曜日なら記録日） |
| 今週〇曜 | 記録日と同じ週（月曜はじまり）のその曜日。記録日より後になるなら confidence を下げる |
| 先週〇曜 | 記録日と同じ週（月曜はじまり）のその曜日の7日前 |

- 曜日は記録日の暦日から数える（推測しない）。週は月曜はじまり
- 「〜から」は始まりの日を `date` にする（例:「点滴の次の日から下痢」→ Day2）
- 「〜まで」は、始まりの日が書かれていればその日、書かれていなければ書かれた終わりの日を `date` にする（例:「先週木曜まで口内炎」→ 先週木曜）
- 日付を決める手がかりが無いときは記録日を `date` にし、`confidence` を下げる（0.5 以下）。推測で日付を広げない
- `day` は `date` を今コースの Day に直したもの（`day1_date` が Day1、その翌日が Day2）。今コースの Day1 より前になったら `day` は null。`course_no` は今コースの番号
- `confidence` は日付と用語の確からしさ（0〜1）。表現どおりに一つに決まるなら高く、迷ったら低く

### 回想

- 出来事の日付が記録日より前なら `recalled: true`（例: Day6 の記録に「おとといは下痢だった」→ Day4、recalled）
- 記録日と同じ日の出来事は `recalled: false`
- 代理入力の記録（`by_proxy: true`）から作った出来事は `by_proxy: true`

### 空白の日を埋めない

- 記録の無い日（入力なし）を埋めない。「入力なし」と「症状なし」は別物
- 回想で書かれた出来事はその日付に置くが、その日を「記録あり」にはしない（経過表はアプリが描き、回想由来の ○ に「回」が付くだけ）
- 書かれていない症状について absent の出来事を作らない。記録の無い日・書かれていない症状を「なし」と推定しない
- 「つらくて書けない」（`too_sick: true`）の記録からは出来事を作らない。症状を推測しない

## 3. 用語（term-mapper）

- `term` は **CTCAE v5.0 JCOG版**の有害事象名から選ぶ（アプリが渡す用語一覧。出典「有害事象共通用語規準 v5.0 日本語訳JCOG版より引用」）。一覧に無い言葉を作らない・言い換えない
- 当てはまる用語が一覧に無い記載は出来事にしない（原文はレポートの引用欄にそのまま載る）
- **Grade を出さない**。重さの語（軽症・中等症・重症・軽度・高度など）も出さない。「つらい」は患者の言葉として引用に残るだけで、重さの判定ではない
- `question_key` は、クローズ質問に対応する症状なら質問の key、対応しなければ null

| 書き方の例 | term の候補 | question_key |
|---|---|---|
| 手足のしびれ、冷たいものにさわるとピリピリする | 末梢性感覚ニューロパチー／錯感覚／異常感覚 | numbness |
| 下痢、お腹がゆるい | 下痢 | diarrhea |
| 口内炎、口の中が痛い | 口腔粘膜炎／口腔内痛 | stomatitis |
| 口の中が痛くて食事がとれない、口内炎で食べにくい | 口腔粘膜炎／口腔内痛 | stomatitis_eating |
| 吐き気、吐いた、食欲がない | 悪心／嘔吐／食欲不振 | nausea_appetite |
| 熱が出た | 発熱 | fever |
| だるい、疲れやすい | 疲労／倦怠感 | null |

## 4. status（あり・改善中・なし）

- `present`: 症状がある。「少しだけしびれる」「軽い下痢」のように程度が小さくても present（程度の言葉は引用に残る）
- `improving`: 改善中（「しびれはだいぶ楽」「口内炎は治ってきた」「昨日よりまし」）。**absent にしない**
- `absent`: 否定（「吐き気はなかった」「下痢は出ていない」）。否定を症状ありにしない
- 1つの記載に複数の症状があれば、症状ごとに出来事を分ける

## 5. 食い違い（contradiction-finder）

- 同じ記録の**同じ日について**、クローズ回答と自由記載が合わないものを `contradictions` に並べる
  - 例: クローズ「下痢 なし」＋自由記載「昼過ぎに下痢」→ `question_key: diarrhea`, `closed_answer: none`, `free_text_quote: 昼過ぎに下痢`
  - クローズ「なし」で、自由記載がその症状を improving としている場合も食い違い（改善中でも症状はある。§4 のとおり absent にしない）
  - 逆向き（クローズ「ある／つらい」＋自由記載「下痢はなかった」）も食い違い
  - 1つの質問が複数の症状をまとめている場合（nausea_appetite＝吐き気・食欲、numbness＝しびれ・冷感、stomatitis＝口内炎・口の中の痛み）は、まとめた症状のどれかが自由記載で present／improving ならクローズ「ある／つらい」と合う。自由記載に出てくるその質問の症状が全部 absent のときだけ食い違い（例: nausea_appetite「ある」で、自由記載では悪心が absent・食欲不振が present → 食い違いではない）
- **食い違いは解決しない**。どちらが正しいかを書かない・選ばない。クローズ回答を書き換えない。並べて示すだけ
- 回想（記録日より前の出来事）は、その記録のクローズ回答との食い違いにしない（別の日のことだから）
- `free_text_quote` も原文の部分文字列そのまま

## 6. 引用

- `source_quote`・`free_text_quote` は、伏せ字後の自由記載（`masked_free_text`）の**部分文字列をそのまま**使う。一字も変えない
  - 要約・言い換え・句読点や空白の追加と削除・全角半角の変換をしない
  - 「○○さん」「[伏せ字]」「[病院]」などの伏せ字もそのまま
  - 離れた2か所をつなげない。その症状が書かれた一続きの部分を短く切り出す
- クローズ回答だけの記録（自由記載なし）からは出来事を作らない（引用が作れない。経過表はアプリがクローズ回答から描く）
- 引用が原文に一致しない出来事は Hook（H2）で拒否される

## 7. 固定規則（緊急時）

- frontmatter の `fixed_rules`: 体温 38.0℃以上の入力で、施設の案内文（`patient_strings.json` の `fixed_rule.fever_38`）を患者画面にそのまま出す
- 判定はアプリのコードの閾値比較。エージェントは関与しない。案内文を作らない・言い換えない

## 8. しないこと

- Grade・重さの判定、トリアージ・受診判断、症状の原因・治療の効果・延期の理由の推測、患者への助言
- 欠けた記録を「症状なし」で埋めること、食い違いを解決すること

## 9. この Skill を書き換えるとき（設定画面 D4）

- `name` は変えない。`version` は承認時にアプリが上げる
- 質問を足すときは新しい `key`（英小文字で始まり、英小文字・数字・下線）を作る。既存の `key` を別の意味に使い回さない（過去の記録がその key を指している）
- 質問文は患者の画面にそのまま出る。助言や説明の文を混ぜない
- `fixed_rules` の `question_key` は `questions` にある key だけ
