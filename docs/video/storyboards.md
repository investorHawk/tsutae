# デモ動画の構成 3 案（案 A・C は 150 秒、案 B は 165 秒で先生の声つき、Remotion）

2026-11-04 Claude 作成。実装は `video/`（Remotion）。3 案は同じ部品を共有し、Studio で切り替えて比べられる。画面の録画は後で撮り、`video/public/footage/<id>.mp4` に置くと差し替わる（置くまでは「何を・何秒撮るか」の枠が出る）。

共通の約束:
- 1920×1080、30 fps。**案 A・C は 150 秒（4500 フレーム）、案 B は 165 秒（2 分 45 秒・4950 フレーム）で先生の声つき**。各案の尺は構成データ（`Storyboard.seconds`）に持たせ、場面の秒数の合計がそれに等しいことをテストで検査する
- 冒頭 15 秒以内に「誰の・どんな課題を・どう解決するか」を言い切る（審査基準デモ 25%）
- 2 つの利点を必ず言葉にする: **医師は短時間で必要な情報が十分に得られる**／**患者は言い忘れなく、日々思っていたことを医師に伝えられる**
- 一本の糸: 患者が Day7 に書いた「おとといの夜から口内炎がいたい」が、レポートの Day5「口内炎」に原文の引用つきで載るところまで追う（見せて伝える）
- 「症例は全て合成（架空）」の札を動画の頭から終わりまでずっと右上に出す（医師画面にはこの注記が無いため動画側で補う）
- 字幕は 2 行以内・1 行 25 字前後・40 px 以上。字幕の文の合計は尺 × 3 字〜尺 × 16/3 字（150 秒で 450〜800 字、165 秒で 495〜880 字。テストで検査）
- `docs/demo-script.md`（4 分の台本）から案 A・C は 90 秒、案 B は 75 秒短い。D5（変換ログの画面）は動画では見せず、仕組みはアニメーションで描く。印刷・未処理・印刷済みは 1 拍ずつ

## 推奨: 案 B「2 分が 20 秒になる」

理由: 先生が挙げた 2 つの利点（医師の時間・患者の言い忘れ）に最も直結し、受賞作の型「使う前後の差を一つの数字で見せる」そのもの。2026-11-06 に先生が案 B を選び、165 秒・先生の声つきにした。冒頭 17 秒は先生の自己紹介（25 年間の消化器外科医）と「何を解決するか」で、聞き取りの「2:00 → 0:20」（先生の実感値。2026-11-06 に 3 分 → 30 秒から直した）は 2〜3 場面目（16〜42 秒）と締めの棒グラフで出る。案 A は物語として引き込みやすく、案 C は「Claude の活用 25%」と安全設計を前面に出す。迷うなら B、技術寄りの審査員を強く意識するなら C。

## 字幕の文

案 A・C は字幕だけで、音声のナレーションは入れない。案 B は「字幕の文」を先生が場面ごとに読み上げ、その声を `video/public/voice/b01`〜`b11` に置く（場面ごとに 1 本。音声ファイルは git に入れない）。表の「字幕の文」の列は構成データの `narration` で、各案の全文と時刻は `docs/video/narration-<a|b|c>.md`（`npm run docs` で構成データから生成）。

## 使い方

```bash
cd video && npm install
npm run studio            # ブラウザで 3 案を切り替えて確認（DemoA / DemoB / DemoC）
npm run render -- DemoB out/demo-b.mp4   # 書き出し（165 秒。数分かかる）
npm run still -- DemoB out/b-60s.png --frame=1800   # 60 秒時点の静止画
npm test                  # 各案の合計が尺（A・C は 150 秒、B は 165 秒）に等しいこと、声の manifest など
```
