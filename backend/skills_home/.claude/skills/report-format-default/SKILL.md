# レポートの形式（既定）

診察室で印刷する A4 一枚のレポートの形式。医師が読んで、設定画面（D4）の一文で直せるように書いてある。

- 上の frontmatter はアプリが読む設定: 並べる欄（`sections`）とその順、前コースの行を出すか（`show_previous_course`）、体温の行を出すか（`show_temperature_row`）、引用の最大件数（`quotes_max_items`）、「？」を付ける確からしさの下限（`low_confidence_threshold`）、要確認に並べる体温（`fever_attention_celsius`）
- レポートはアプリが決まった手順で描く。AI が決めるのは「4. 症状別の時系列」に何を載せるかだけ
- モノクロ印刷で読めるように、色は使わず網掛けと記号で区別する
- **Grade は一切出さない**。重さの判定語（軽症・重症など）も出さない

## 1. ヘッダ（header）

- 受付番号、仮名ID、レジメン、コース番号と期間（Day1 の日付〜最終日）
- 記録日数（例: 11日/14日、内訳: 入力なし2・つらくて書けない1）
- 延期があれば「延期（予定より○日）」。理由は書かない
- AI 変換ができなかったときは「AI変換なし」と書く（経過表と原文引用だけのレポートになる）

## 2. 要確認（attention）

医師が最初に読む欄。上から順に:

- ▲ 食い違い: Day、クローズの回答、自由記載の引用。どちらが正しいかは書かない
- ▲ 発熱: 体温が 37.5℃以上の日の Day と体温
- ● つらくて書けない: その Day。前コースの同じ Day にもあれば併記する
- 未処理の記載あり: 伏せ字漏れの疑いで AI に送らなかった記録の件数だけ（中身は院内画面 D6 で見る。紙には載せない）

## 3. 経過表（grid）

- 行 = クローズ質問の項目＋体温。列 = Day1〜14（コースが延びればその日まで）
- 今コースの下に前コースの行を並べる。前コースの行はクローズ回答だけ（AI 変換は今コースだけ）。毎コース同じ Day の「つらくて書けない」が縦に揃って見える
- セル: なし = 薄い「−」、ある = 網掛け、つらい = 濃い網掛け、入力なし = 空白、未設問（その日はまだ無かった質問） = 「−−」
- 「つらくて書けない」の日は列全体を斜線
- 自由記載にその症状の記述があれば ○ を重ねる（クローズ「なし」の上の ○ は食い違いとして目で分かる）
- 代理入力の日は列頭に「代」、回想由来の ○ には「回」
- 凡例を欄外に固定で印刷する

## 4. 症状別の時系列（per_symptom）— AI が選ぶ欄

主エージェントが `emit_report` で渡すのはこの欄だけ。時系列（timeline）の出来事から選ぶ:

- 症状（用語名）ごとに1行。用語名は CTCAE v5.0 JCOG版の名前そのまま（欄外に「有害事象共通用語規準 v5.0 日本語訳JCOG版より引用」）
- 開始 Day と開始日: その症状が present か improving で最初に出た日
- 代表引用: その症状をよく表す出来事の `source_quote` を1つ、そのまま（言い換えない・つなげない）
- 確からしさ: 代表引用に選んだ出来事の `confidence`。0.6 未満は「？」を付けて印刷される
- 否定（absent）だけの症状は載せない。並べ順は開始 Day の早い順
- 重さ・原因・見通しを書かない

## 5. 引用（原文）（quotes）

- 自由記載を Day 順に、伏せ字後の原文のまま並べる。代理入力には「代」
- 最大 30 件。一枚に収まらなければ引用欄を2枚目に回す

## この形式を書き換えるとき（設定画面 D4）

- `name` は変えない。`version` は承認時にアプリが上げる
- 欄の並べ替え・省略は `sections` を直す（header, attention, grid, per_symptom, quotes から選ぶ）
- 数値の設定（引用の件数、「？」の下限、要確認の体温）は frontmatter の値を直し、本文の説明も同じ値に直す
- frontmatter に無い項目は足さない（アプリの検査で拒否される）。本文だけを直しても印刷の見た目は変わらない
