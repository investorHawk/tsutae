## 注意
- 撮影中に本物の Claude が失敗して「AI変換なし」や「失敗」になったら、印刷待ちの行の「AI でもう一度変換」を押す（D5 に `regenerate_requested` と2回目の変換が出る）。それでも駄目なら「AI変換なし」のレポートを見せ、フォールバックの説明に切り替える（spec 6 の必須の動き）
- サーバーを止めると生成中の受診は止まる。起動し直すと「AI変換なし」で回収される（`orphan_recovered`）。その後「AI でもう一度変換」で作り直せる
- 9 と 12 は本物の Claude を呼ぶので、撮る前に1回通しておく（9 は `run_demo_regimen.py`、12 は `run_demo_skill_change.py`）。9 の往復が失敗すると会話に失敗の行が出てフォームは変わらない（「…。フォームは変わっていません。もう一度送ってください」）。そのときは同じ文をもう一度送るか、文を短くする。12 が失敗したら差分が出ずに「失敗」になる。そのときは依頼文を短くして撮り直す
- 既存のレジメンのタブを押すと版 N+1 の下書きができて残る。撮影の前に、要らない下書きは「下書きを捨てる」で消す

- 10 で採用した後・12 で承認した後に撮り直すときは、撮影用 DB と Skill を元に戻す必要がある（採用は新しいフォルダ `regimen-folfiri-bv/` と DB の版・フォームを作り、承認は本体の SKILL.md を書き換える。同じ識別名はもう作れない）。**撮影は `TSUTAE_SKILLS_DIR` で Skill の写しを指して行い、撮り直すたびに写しと撮影用 DB を新しく作る**: `cp -R backend/skills_home data/skills-take1` して `TSUTAE_SKILLS_DIR=data/skills-take1/.claude/skills`、DB は `.venv/bin/python scripts/seed_demo.py --db data/demo-take2.db --device-records`（既存の DB は消さない）。患者の端末も「撮影の前に」の撮り直しの手順で戻す
